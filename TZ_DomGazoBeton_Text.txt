ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Проект: "Цифровой клиентский сервис DomGazoBeton"

═══════════════════════════════════════════════════════════════

1. ОБЩАЯ ИНФОРМАЦИЯ О ПРОЕКТЕ

1.1 Название проекта
"DomGazoBeton Digital Client Hub" - Telegram Mini App для автоматизации клиентского взаимодействия

1.2 Заказчик
Строительная компания полного цикла "DomGazoBeton"
- Специализация: проектирование и строительство домов из газобетона
- Масштаб: одновременное строительство более 50 домов

1.3 Описание решения
Комплексная цифровая платформа на базе Telegram Mini App для автоматизации взаимодействия с клиентами строительной компании DomGazoBeton. Система включает персональный кабинет клиента, административную панель и автоматизированные процессы документооборота, опросов и уведомлений.

1.4 Проблемы, которые решает проект
1. Неэффективный документооборот - отсутствие централизованного доступа к документам проекта
2. Низкая скорость коммуникации - задержки в получении обратной связи и информации
3. Ручная обработка документов - трудозатратные процессы подписания и контроля
4. Отсутствие структурированной обратной связи - нет системного сбора NPS данных
5. Информационная разрозненность - множественные каналы коммуникации без единой точки доступа

1.5 Цель проекта
Создание единой цифровой экосистемы для повышения качества клиентского сервиса и операционной эффективности компании DomGazoBeton.

1.6 Гипотеза
Внедрение централизованной цифровой платформы позволит:
- Увеличить NPS клиентов на 15-20%
- Сократить время обработки документов на 40%
- Повысить вовлеченность клиентов в процесс строительства
- Снизить нагрузку на сотрудников по рутинным задачам на 30%

1.7 Ожидаемые результаты
- Сокращение времени на обработку документов в 2-3 раза
- Увеличение скорости получения обратной связи от клиентов
- Повышение прозрачности процессов строительства
- Снижение нагрузки на сотрудников по рутинным задачам
- Улучшение имиджа компании как технологичной организации

2. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА

2.1 Технологический стек
- Backend: Laravel 10+ (PHP 8.2+)
- Database: MySQL 8.0+
- Frontend Mini App: Vue.js 3 / React (в рамках Telegram Mini App)
- Queue System: Redis + Laravel Queue
- File Storage: Laravel Storage (локальный сервер)
- API Integration: Bitrix24 REST API, Telegram Bot API

2.2 Архитектурные принципы
- Микросервисная архитектура внутри монолита Laravel
- RESTful API для взаимодействия с Mini App
- Event-driven уведомления
- Принцип YAGNI (You Aren't Gonna Need It)

2.3 Масштаб системы
- Клиенты: до 150 пользователей
- Сотрудники: до 40 пользователей
- Админы: неограниченно (управляется через систему ролей)

3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

3.1 Система ролей и авторизации

3.1.1 Роли пользователей
- Админы: полный доступ к системе, управление пользователями
- Сотрудники: работа с клиентами, отправка документов и опросов
- Клиенты: доступ к личному кабинету

3.1.2 Права доступа
- Админы могут добавлять/удалять сотрудников и других админов
- Сотрудники имеют доступ только к назначенным им клиентам
- Клиенты видят только свои данные

3.1.3 Авторизация
- Авторизация через Telegram (без дополнительной регистрации)
- JWT токены для API взаимодействия
- Автоматическое создание профиля при первом входе

3.2 Модуль документооборота

3.2.1 Структура документов

- Типы: Договоры, Акты, Отчеты, Дополнительные соглашения

3.2.2 Функционал для клиентов

- Подписание документов (цифровая подпись)

3.2.3 Функционал для сотрудников

3.2.4 Система уведомлений
- Клиенту: новый документ для подписания
- Сотруднику: документ подписан клиентом
- Канал доставки: Telegram Bot

6. ПОЛЬЗОВАТЕЛЬСКИЕ СЦЕНАРИИ

6.1 Сценарий использования клиентом

Получение уведомления о новом документе:
1. Клиент получает уведомление в Telegram от бота
2. Переходит в Mini App по кнопке в сообщении
3. Авторизуется автоматически через Telegram
4. Видит новый документ в соответствующей категории
5. Просматривает документ и подписывает его
6. Получает подтверждение о успешном подписании

Прохождение NPS опроса:
1. Получает уведомление о необходимости пройти опрос
2. Переходит в Mini App
3. Проходит опрос по текущему этапу строительства
4. Оставляет комментарий (опционально)
5. Получает благодарность за участие

Поиск информации в FAQ:
1. Открывает Mini App
2. Переходит в раздел FAQ
3. Использует поиск или выбирает категорию
4. Находит ответ на интересующий вопрос

6.2 Сценарий использования сотрудником

Отправка документа на подпись:
1. Входит в административную панель
2. Выбирает клиента из списка назначенных
3. Загружает документ и указывает категорию
4. Отправляет документ на подпись
5. Получает уведомление о подписании документа клиентом

Запуск опроса для клиента:
1. Выбирает клиента и текущую стадию проекта
2. Выбирает соответствующий шаблон опроса
3. Отправляет опрос клиенту
4. Отслеживает результаты в реальном времени

Работа с новостями:
1. Создает новость или уведомление
2. Выбирает целевую аудиторию
3. Планирует время отправки (или отправляет сразу)
4. Отслеживает статистику доставки

6.3 Сценарий использования администратором

Настройка системы:
1. Управляет пользователями и их ролями
2. Настраивает стадии проектов и привязанные опросы
3. Создает и редактирует шаблоны опросов
4. Настраивает интеграции с внешними системами

Анализ данных:
1. Просматривает дашборд с ключевыми метриками
2. Анализирует NPS данные по периодам и этапам
3. Изучает статистику использования системы
4. Экспортирует данные для дальнейшего анализа
